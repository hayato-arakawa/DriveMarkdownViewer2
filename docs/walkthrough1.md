# フォルダプレビューにおけるボタン配置と描画崩れ修正結果 (Drive Markdown Viewer)

Google Driveのフォルダ画面（`drive/folders/*`）上のプレビュー（`file/d/*` へのURL遷移を伴わないモーダルオーバーレイ表示）において、「MD」ボタンが正しく表示・機能しない問題を、プレビュー判定の厳密化、複数ドキュメント選択バグの解消、および非表示手法の改善によって完全に修正しました。

## 1. 発見されたバグと修正内容

### バグ1: `isPreviewPage()` の判定ミスとオブザーバーの早期停止
- **問題:** プレビュー判定に使用していた `div.a-b-r` というクラスが、プレビューが閉じた状態（通常のフォルダリスト画面）のDOMにも常に存在していたため、ページロード時に「プレビュー中」と誤判定されていました。これにより、プレビュー起動前にDOM監視オブザーバーが停止（`cleanupObserver()`）し、実際にプレビューが開かれた際にボタンが注入されない状態になっていました。
- **対策:** [content.js](file:///Users/nakamegurokoumylab/Downloads/DriveMarkdownViewer/DMV/content.js#L16-L23) にて、プレビューダイアログ専用のツールバー要素（`div.a-b-K[role="toolbar"]`）の存在を基準に判定するよう変更し、またボタンが実際にDOMに作成されたことを確認した上でオブザーバーを停止するようにライフサイクルを修正しました。

### バグ2: 複数プレビュー要素混在時のドキュメント誤特定
- **問題:** フォルダ画面で連続してプレビューを開き直した際、以前のプレビューのDOM（`display: none`）が残存し、拡張機能が非アクティブな旧ドキュメントからテキストをスクレイピングしようとして失敗していました。
- **対策:** アクティブな（現在表示中の）ドキュメント要素のみを特定するヘルパー関数 `findActiveDocument()` を追加し、スクレイピング対象を動的かつ正確に特定するようにしました。

### バグ3: `display: none` によるレイアウト崩れ
- **問題:** Markdown表示時に元のコンテンツ要素を `display: none` にすると、Google Drive側の親コンテナの高さや幅が `0` に縮小（レイアウト崩れ）してしまい、絶対配置のMarkdownビューワが画面上に表示されなくなる現象が発生していました。
- **対策:** 元の要素を非表示にする手段を `display: none` から `visibility: hidden`（空間は確保したまま非表示にする）に変更し、レイアウトが崩れないように改善しました。
